# Матрица Buy vs Build для VitaStore

## Sourcing Strategy

Стандартные магазинные функции, которые не дают VitaStore уникального конкурентного преимущества, целесообразно перевести на SaaS-решения. Это позволит убрать локальные серверы из магазинов, снизить расходы на поддержку legacy-систем и унифицировать процессы после покупки региональных сетей.

Уникальные возможности HQ, связанные с омниканальной логистикой, доступностью товаров и Click & Collect, лучше развивать In-house. Их можно переносить на PaaS/IaaS, чтобы снизить инфраструктурную нагрузку, но бизнес-логику и архитектурный контроль стоит сохранить внутри компании.

## Buy vs Build

| Возможность | Целевая модель | Решение | Обоснование |
|---|---|---|---|
| Касса / POS | SaaS | Buy | Стандартная ритейл-функция, не создаёт уникального конкурентного преимущества. |
| Возвраты и закрытие смены | SaaS | Buy | Типовой кассовый процесс, который должен быть унифицирован во всех магазинах. |
| Печать ценников | SaaS / Cloud service | Buy | Commodity-процесс, должен получать данные из ERP и Promo Engine. |
| Локальное обновление цен | SaaS / ERP integration | Buy | Лучше заменить локальную логику централизованной синхронизацией цен. |
| Программа лояльности | SaaS / PaaS | Buy / Migrate | Базовую механику можно купить, а интеграцию с Promo Engine и клиентскими данными оставить под контролем компании. |
| Ручной учёт клиентов и бонусов | SaaS | Buy | Ручной процесс нужно заменить централизованной системой лояльности. |
| Локальный расчёт премий продавцам | SaaS | Buy | Типовая HR/KPI-функция, которую лучше централизовать и стандартизировать. |
| Локальные KPI и правила начислений | SaaS / ERP HR module | Buy | Дублирует корпоративные HR и ERP-процессы. |
| Приём товара от локальных поставщиков | SaaS / ERP module | Buy | Процесс можно унифицировать через ERP или стандартный supply chain module. |
| Локальный учёт остатков | ERP / PaaS | Migrate | Остатки должны быть централизованы, чтобы поддерживать омниканальные сценарии. |
| Инкассация и сверка платежей | SaaS | Buy | Стандартизированный финансовый процесс, не является дифференциатором. |
| Серверы в подсобках магазинов | PaaS/IaaS | Migrate | Необходимо убрать локальную инфраструктуру и перенести вычисления и данные в облако. |
| Локальные базы данных магазинов | PaaS/IaaS | Migrate | Данные нужно централизовать, используя управляемые базы данных и интеграционные сервисы. |
| ERP HQ | PaaS/IaaS / In-house | Migrate / Keep | ERP уже централизована; инфраструктуру можно постепенно переносить в облако, сохранив контроль над критичными данными. |
| Promo Engine | In-house / PaaS | Build / Migrate | Важная централизованная система управления промо и маржой, может быть дифференциатором. |
| Smart Fulfillment | In-house / PaaS | Build | Главное конкурентное преимущество VitaStore, бизнес-логику нельзя отдавать как commodity. |
| Click & Collect | In-house / PaaS | Build | Ключевой клиентский сценарий, напрямую связан со Smart Fulfillment. |
| Резервирование товара со склада | In-house / PaaS | Build | Критично для точности доступности товара и качества омниканального сервиса. |
| Расчёт доступности товара для клиента | In-house / PaaS | Build | Дифференциатор, влияющий на клиентский опыт и эффективность логистики. |
| Аналитика продаж и запасов | SaaS BI / PaaS | Buy / Build | BI-платформу можно купить, но модели прогнозирования и оптимизации стоит развивать внутри. |
