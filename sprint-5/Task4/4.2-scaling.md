# 4.2. Стратегия горизонтального масштабирования

Две наиболее критичные системы для новой нагрузки — сервис API мобильного приложения и расписание: через них проходит основной сценарий самозаписи, а блокировки расписания уже подтверждены. Нагрузка на legacy-систему 1С снижается с помощью кэша и ограничения входящего потока; оснований предлагать её прямое горизонтальное масштабирование в исходных данных нет.

| ИТ-система | Реализация горизонтального масштабирования | Ограничение | Решение ограничения |
|---|---|---|---|
| Сервис API мобильного приложения | Сделать экземпляры stateless и запустить несколько копий за load balancer. Access token передаётся в формате JWT; каждый экземпляр проверяет его подпись и claims, поэтому локальная пользовательская сессия не нужна. Идемпотентность обеспечивается общим хранилищем. Перед ожидаемыми вечерними пиками и выходными количество экземпляров увеличивается по расписанию | Общая БД или хранилище идемпотентности может стать узким местом | Индексы и пул соединений, затем read-replica для чтения; нагрузочное тестирование определяет число экземпляров |
| Расписание | Несколько экземпляров Java-сервиса за балансировщиком; read-replica PostgreSQL для поиска врачей/слотов, primary для создания и отмены записи | Реплика может отставать, а конкурентная запись в один слот остаётся на primary | После команды читать подтверждение с primary; уникальное ограничение на слот и короткая транзакция/оптимистическая блокировка предотвращают двойную запись |

Основная мощность выделяется заранее: количество экземпляров рассчитывается так, чтобы в ожидаемый пик их загрузка составляла около 60%. Поскольку вечерние и выходные пики предсказуемы, перед ними количество экземпляров увеличивается по расписанию. Реактивное масштабирование по RPS, CPU и времени ответа используется только как дополнительная защита от продолжительного превышения прогноза, поскольку запуск новых экземпляров занимает время. Для каждого критичного сервиса постоянно работает не менее двух экземпляров, чтобы отказ одного из них не останавливал пользовательский сценарий.
