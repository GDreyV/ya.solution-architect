# План переключения

Источник: [смета HA](../Task2/options-comparison.md), [НФТ](../Task3/nfr-registry.md). Владелец — SRE; при его отсутствии резервный дежурный. CTO руководит длительным инцидентом.

## Assumptions

NG-1/2: API и DB; NG-3: DB. etcd — три участника на DB-узлах. Синхронное подтверждение хотя бы одной подходящей реплики, Patroni strict/quorum и проверенное fencing. Все площадки — Lagos. Цели ниже требуют испытаний.

| Отказ | Решение и шаги | Кто | Время | Потери |
|---|---|---|---|---|
| API-процесс | Health-check → исключить endpoint → перезапустить → проверить | Автоматика; дежурный контролирует | Цель ≤30 с для новых подключений | Подтверждённые записи сохраняются |
| Primary/один ЦОД | Проверить кворум → изолировать старый primary → повысить допустимую реплику → переключить HAProxy и DNS → сверить заказы | Patroni и маршрутизация; дежурный | Цель ≤120 с | RPO=0 подтверждённых записей |
| Межплощадочная сеть | Сторона без кворума останавливает запись; продолжает только безопасная сторона | Автоматика, SRE | Цель ≤120 с при доступных двух копиях | RPO=0; доступность зависит от связности |
| Весь Lagos / большинство DB | Остановить запись → сообщить статус → восстановить площадку/кворум → проверить данные → открыть трафик | CTO + SRE + провайдер | Нет | RPO зависит от сохранности локальных копий |
| Логическое повреждение БД | Остановить запись → восстановить backup + WAL в изоляции → сверить → переключить | SRE, разрешение backend-2 | Цель ≤4 ч | Цель RPO ≤15 мин |
| CDN / облачный edge | Переключить клиент на локальную публичную статику; API работает напрямую | Автоматика, frontend | Цель ≤120 с | Заказы сохраняются |
| Платёжный партнёр | Circuit Breaker → pending → сверка после восстановления | Backend-2 | Зависит от партнёра | Не повторять неизвестное списание |

Проверка готовности API должна включать возможность записи в актуальный primary. DNS-кеш и повторное подключение проверяются в мобильных сетях. Если 120 с не достигаются, маршрут пересматривается до запуска.

Возврат площадки: очистить старую роль → догнать реплику → проверить lag и fencing → постепенно вернуть трафик. Автоматическое обратное переключение отключено.

Перед запуском отключить по очереди каждый узел, ЦОД и канал; проверить разделение сети, повтор запроса, восстановление копии и отказ CDN. Записать время и сверить ID подтверждённых заказов.
