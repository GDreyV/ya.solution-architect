# ADR-002. Стратегия кеширования

**Статус:** предложено. **Владельцы:** CTO, backend-1.

## Контекст

[Маркетинг](../artifacts.md#artifact-2) требует быстрый каталог при дорогом мобильном интернете. [ADR-001](../Task2/adr-001-architecture-style.md) выбирает модульный монолит.

## Драйверы решения

Задержка, небольшой бюджет, актуальность цены и остатков.

## Решение

Статическую часть карточки — описание, характеристики и разметку — раздаём через CDN по `/products/123/rev/<hash>.html`. При изменении создаём новую ревизию. Цену и остаток загружаем отдельно через API.

| Данные | Место | TTL | Инвалидация |
|---|---|---|---|
| Публичные фото, JS/CSS | Front Door и клиент | 24 ч | Новое имя с хешем; purge при удалении |
| HTML публичной карточки по ревизии | Облачный origin, Front Door и клиент | 1 год; `public, max-age=31536000, immutable` | Новый URL при изменении; существующий файл не перезаписывается |
| Поисковая выдача со ссылками на ревизии | Память API, ключ с фильтрами; HTTP no-store | 30сек | TTL |
| Отображаемые цена и остаток | Redis, Cache-Aside; HTTP no-store | 30сек, страховочный | Удаление ключа после изменения в PostgreSQL через outbox |
| Профиль, заказ, платёж | PostgreSQL; HTTP no-store | 0 | Чтение актуального состояния |

Worker по событию outbox публикует HTML и версионные ресурсы в origin, затем обновляет ссылку на ревизию в БД. Старые файлы не перезаписываются; запоздавшие события не откатывают ревизию.

При обновлении purge не нужен. При снятии товара удаляем его из выдачи и origin, очищаем CDN и блокируем покупку; браузерные копии отозвать нельзя.

Кеш поиска — 256 MiB на API-узел, LRU, объединение одновременных загрузок одного ключа. При отказе CDN используем резервный адрес origin.

Redis размещаем в облачном контуре каталога. При промахе читаем цену и остаток из PostgreSQL и кешируем по SKU и варианту цены. Изменение цены или доступного остатка, включая резервирование, записывает событие инвалидации в той же транзакции. При отказе Redis читаем БД с ограничением нагрузки; PostgreSQL остаётся источником истины.

## Рассмотренные альтернативы

Cache-Aside карточек в API уступает CDN по разгрузке приложения. Чтение цены и остатка напрямую из БД проще, но Redis снижает нагрузку и даёт общий кеш для API-узлов.

## Последствия

CDN и Redis разгружают API и БД; нужны генерация HTML, хранение ревизий и эксплуатация Redis. Поиск может ещё 30сек возвращать старую ссылку. Инвалидация асинхронна; TTL ограничивает жизнь устаревшей записи, в том числе при гонке заполнения кеша. Цена и наличие при покупке проверяются в БД.

Основание для долгого кеширования версионных URL: [MDN — HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching).

## Пересмотр и late binding

Размер Redis и TTL уточняем по cache hit rate, нагрузке на БД и задержке инвалидации.

## Assumptions

TTL и размер кеша — стартовые настройки для нагрузочного теста. Стоимость Redis ещё не включена в смету Task2 и требует оценки.
