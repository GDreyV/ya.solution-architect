# 3.2.1. DWH и Data Lakehouse

| Аспект | DWH на PostgreSQL | Data Lakehouse |
|---|---|---|
| Назначение | Регламентированная отчётность, согласованные витрины | Большая история, события, архивы, полуструктурированные данные |
| Модель | Реляционные факты и измерения | Таблицы поверх объектного хранилища |
| Доступ | SQL и BI | SQL через Trino, пакетная и потоковая обработка |
| Сильная сторона | Контролируемые показатели и понятные сверки | Масштабирование хранения и разнообразие данных |
| Ограничение | Не предназначено для всех исходных событий и архивов | Требует каталога, управления схемами и дисциплины качества |

Через три месяца используется DWH на PostgreSQL для единой управленческой отчётности. Через 12 месяцев DWH сохраняется для регламентированной отчётности, а Lakehouse принимает историю операций, события каналов и архивные выгрузки.

Apache Iceberg задаёт табличный формат Lakehouse, версии схем и снимки таблиц. Trino предоставляет SQL-доступ к этим таблицам. Эти технологии не заменяют DWH: в DWH остаются проверенные факты, измерения и отчётные витрины.

Ограничения решения: два аналитических контура требуют согласованных правил публикации, общего каталога и контроля, чтобы показатели DWH и Lakehouse не расходились.
