## 3. Оценка качества

| Поле | Решение |
|---|---|
| Бизнес-метрика | Число обоснованных направлений на углубленную проверку; время разбора и ожидания проверки |
| Ожидаемый результат | Более качественная очередь и ускорение разбора дают эффект, превышающий дополнительные затраты на решение за тот же период. Минимальное улучшение времени и/или качества очереди рассчитывается из сметы и согласованной денежной оценки эффекта до пилота; расчёт — в [Task4](../Task4/cost.md#как-определить-требуемое-улучшение). Высвобождённая мощность учитывается отдельно от денежной экономии |
| Положительный класс | Для оценки отбора — операция, для которой эксперты по единому порядку проверки подтвердили необходимость углубленного разбора. Это не класс «подтверждённая схема» |
| Метрика под решение | Доля таких операций среди отобранных на проверку при фиксированном размере очереди; дополнительно — доля пропущенных экспертных подозрений по независимой выборке |
| Baseline | Около 10 тыс. разборов в месяц по 12 минут; около 400 эскалаций. Исторические 4% — частота эскалаций, а не точность выявления схем |
| Проверочная выборка | К ML-специалистам |
| Рабочая точка | Определяется по нагрузке отдела |
| Показатели в этой точке | Берется из ответа модели |
| Цена ошибок | Ложный приоритет тратит время и отодвигает другую операцию; пропуск задерживает выявление. Автоматической приостановки по оценке модели нет |
| Guardrails | Сохраняются обязательные проверки; не растут задержки обязательного разбора, лишние приостановки и жалобы; результаты модели не интерпретируются как доказательство схемы |

Размер независимой выборки определяется до запуска совместно с финансовым мониторингом по требуемой точности оценки и доступному времени. Отбор должен иметь известную ненулевую вероятность включения для каждой операции. Для оценки всего потока учитываются эти вероятности; результаты только приоритетной очереди не переносятся на весь банк.

## 4. Готовность данных

| Поле | Оценка и действие |
|---|---|
| Источник правильного ответа | Экспертная оценка для очереди. Эскалация, исход расследования и формальное подтверждение хранятся раздельно, вместе с датой появления |
| Качество, объём по важному классу, разметка, смещение отбора, репрезентативность | Уточняется у профильного отдела Data Science / ML-инженеров |
| Право использовать | Цель, состав полей, доступ и хранение согласуются с комплаенсом, ответственным за защиту данных и юристами; передача за контур рассматривается отдельно |
| Владелец | Предлагаемые ответственные роли: История операций и справочники банка; доступ подтверждает владелец соответствующего источника. Финансовый мониторинг отвечает за смысл экспертных заключений. Конкретные владельцы требуют подтверждения. |
| Вердикт | Разрыв с планом закрытия: согласовать доступ, сформировать и проверить обучающую историю с исключениями, подготовить экспертные критерии, контрольную выборку и проверочный набор. Затем возможен теневой пилот приоритизации |


## 5. Карточка эксперимента

Гипотезы для проверки:

1. **Рекомендации согласуются с оценкой экспертов.** В теневом режиме (shadow testing) операции с высоким рекомендованным приоритетом эксперты независимо оценивают как требующие первоочередного внимания. Сравниваем именно приоритет проверки, а не вердикт о нарушении.
2. **Новый порядок полезнее текущего.** При том же доступном времени сотрудников предложенная очередь позволяет раньше рассмотреть больше операций, которые эксперты считают важными для углублённой проверки.
3. **Рекомендации удобны в работе.** Сотруднику понятны основания приоритета; их изучение не увеличивает общее время разбора операции.
4. **Обязательная работа не страдает.** Использование рекомендаций не задерживает обязательные проверки и не создаёт непосильную очередь.
5. **Улучшение оправдывает затраты.** Сокращение времени разбора и польза нового порядка достигают минимального уровня, рассчитанного до пилота из стоимости решения. Финансовый мониторинг и владелец бюджета согласуют способ оценки эффекта и целевые значения; по результатам пилота проверяем, превышает ли денежный эффект дополнительные затраты за выбранный период.

В теневом режиме система формирует рекомендации параллельно текущему процессу, эксперты сначала фиксируют собственную оценку без подсказки. Согласованность и предполагаемую пользу очереди проверяем сравнением результатов. Удобство и время работы с рекомендациями проверяем отдельно в пробном разборе без влияния на реальные платежи. Допустимые расхождения и условия перехода к пилоту согласуются с финансовым мониторингом; совпадение оценок само по себе ещё не доказывает улучшение процесса.
