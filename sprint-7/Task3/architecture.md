# Задание 3. Архитектура сервиса приоритизации

Схемы C4: [флагман — Container и Component](flagship-c4.md), [№ 2 и № 18 — Container](documents-c4.md). Постановка — [Task1](../Task1/passport-01.md), решение — [ADR-001](../Task2/adr-001.md).

## Ответственность и режим обработки

Обычный код получает операцию и предыдущую историю клиента, модель возвращает числовую оценку нетипичности, программа объединяет её с сигналами контроля и рассчитывает приоритет. Сотрудник принимает решение по операции. Модель не блокирует платежи.

Оценка запускается при поступлении каждой помеченной операции, асинхронно относительно проведения платежа, без ожидания пакета. Допустимую задержку согласует финансовый мониторинг. До получения результата действует исходный приоритет. Повторы не создают дубликатов, запоздалый ответ не заменяет результат для более новой версии данных.

Текущая операция не входит в историю сравнения. Из обучающей истории исключаются подтверждённые нарушения и незавершённые проверки; обычный код уточняет её состав по исходам расследований. Модель обновляется отдельно. Отсутствие подтверждения не доказывает безопасность истории; при её нехватке работают правила.

Очередь сохраняет обязательные проверки и сроки, независимую контрольную выборку и защиту от бесконечного ожидания. Остальной ресурс распределяется по приоритету. Ориентир — 2 тыс. часов ручной работы в месяц; контроль и повторные проверки входят в этот ресурс. Детали выбора и оценки модели уточняет DS/ML-отдел, допустимую нагрузку — финансовый мониторинг.

## Выходной контракт флагмана

Контракт сервиса объединяет оценку модели и сведения обычного кода. Позицию в очереди рассчитывает программа.

| Поле | Смысл и проверка |
|---|---|
| `operation_id`, `source_ref` | Обязательные идентификатор и ссылка на исходную операцию; проверяются существование и права доступа |
| `calculated_at`, `data_as_of`, `input_version` | Обязательные время расчёта, срез и версия входа; исключаются будущие и устаревшие данные |
| `model_version`, `policy_version` | Версии модели и правил; модель обязательна только при её запуске, правила — всегда |
| `status`, `anomaly_score` | `ranked` и конечная числовая оценка либо `fallback` без оценки; диапазон определяется контрактом кандидата |
| `reason_codes`, `rule_signals`, `mandatory_priority` | Обязательные основания и сигналы контроля; модель не может отменить обязательный приоритет |
| `selection_origin`, `inclusion_probability` | Основание отбора обязательно; вероятность включения обязательна для независимой выборки и находится в интервале (0; 1] |

До изменения очереди код проверяет поля, версии и актуальность ответа. Сотруднику показываются основания и исходная операция; его заключение сохраняется отдельно от оценки модели.

## Fallback — резервное поведение

| Ситуация | Действие |
|---|---|
| Нет данных, история устарела или недостаточна, случай вне проверенной области | Использовать исходный порядок контроля |
| Низкая оценка противоречит обязательному сигналу | Сохранить обязательный приоритет |
| Отказ модели, тайм-аут, превышение лимита или некорректный ответ | Отклонить результат, сохранить исходный приоритет и записать ошибку |
| Равные оценки | Использовать исходный порядок для разрешения равенства |
| Нарушаются обязательные сроки или доступная нагрузка | Остановить влияние модели и вернуться к текущему процессу |

## Мониторинг

| Что наблюдаем | Реакция |
|---|---|
| Полнота и актуальность входа, новые сегменты | Резервный маршрут для непригодных данных; повторная оценка применимости с DS/ML-отделом |
| Ошибки, длительность расчёта, версии и изменение оценок | При отказе — fallback; при устойчивом изменении — повторная проверка качества |
| Возраст очереди, обязательные сроки, труд сотрудников и контрольная выборка | При нарушении ограничений — остановка влияния модели |
| Согласованность с экспертами, полезность очереди и время разбора | Сравнение с целями из [плана пилота](../Task4/pilot.md); при ухудшении — пересмотр или откат |
| Лишние приостановки, жалобы, нарушения доступа | Разбор причин; при нарушении согласованных ограничений — остановка затронутого процесса |

## Угрозы на границах доверия

| Граница | Угроза и защита |
|---|---|
| G1: источник → сервис | Избыточный доступ или неверные данные: минимальные права, проверка идентификаторов и времени |
| G2: сотрудник → интерфейс | Доступ к чужим операциям или принятие подсказки за факт: ролевой доступ, исходные сведения и журнал решений |
| G3: сервис → аудит | Утечка содержимого: в технических журналах только идентификаторы и события |
| G4: модель → код | Непригодный ответ: проверка контракта до изменения очереди |
| Поставка модели и зависимостей | Подмена: проверка происхождения, целостности и версии перед запуском; обновление после приёмки |
| Внутренний контур → провайдер | Несогласованная передача: внешние вызовы не используются; изменение требует пересмотра [размещения](../Task2/data-boundaries.md) |

Языковая модель, внешние инструменты и поиск для флагмана не нужны. Назначение платежа доступно сотруднику как исходный текст. Обработка недоверенных документов описана в [схеме № 2 и № 18](documents-c4.md).
